# UI 组件模块

ElenixOS UI 建立在 LVGL 上，但 UI 的所有权和层级由 Activity、顶层图层注册表和系统 UI 管理器共同约束。组件不是任意 LVGL 对象的集合。

## UI 模型

Activity 拥有应用页面 View；系统级组件使用语义化 top-layer slot。slot 对应永久容器并表达应用内容、页面快照、应用头部、全局交互、系统 UI、模态 UI、安全 UI 和调试 UI 的层级关系。slot 编号是排序语义，不是 LVGL child index，也不能持久化。

消息列表、控制中心和其他同级 overlay 共享 interaction slot。slot 内部的前景对象和触摸对象通过统一 focus 机制调整顺序，避免各组件分别抢占 top layer。模态、锁屏、错误和权限 UI 位于规定的更高层级。

## 职责

- Activity 管理页面 View、页面过渡和页面销毁。
- Overlay layer 管理系统级容器和稳定的视觉层级。
- Interaction slot 管理同级可交互 overlay 的当前焦点和输入对象。
- 组件负责自己的内部对象和回调，但不负责删除共享 slot、Activity View 或其他组件的根对象。
- 脚本通过已注册的 `lv`/`eos` API 创建对象；脚本句柄仍受所属 View 和程序生命周期限制。

## 输入与渲染流程

输入设备没有共用一个能替所有输入作决定的事件队列。平台触摸通过 LVGL pointer indev 交给触摸输入层，再由 LVGL 对象树进行命中和控件事件分发。表冠旋钮绑定当前可滚动对象；表冠键和侧键先被转换为系统动作，再经主循环调度到 Chrome 或电源管理。页面和 overlay 的前景关系由 Activity/Chrome 管理，不由驱动推断。

因此平台移植应报告标准化的触摸、旋钮或按键状态；页面导航、唤醒、打开控制中心和控件交互仍由系统层处理。UI 回调在 LVGL/运行时主循环中执行；渲染输出由平台显示端口承载。

## 消息列表与通知边界

消息列表是放在共享 interaction slot 中的 UI 组件，负责列表项和详情的显示。当前实现没有通用通知 broker、通知持久化服务或面向 JS 的通知投递 API。`notification` 权限类别及设置入口本身不构成通知发送/存储契约；该列表 UI 不应被视为通知服务的 owner。

## 架构约束

- 系统组件必须使用语义 top-layer slot，不得依赖当前 child index 或私自重排共享 top layer。
- 同级 overlay 必须通过 interaction slot 获得焦点；系统模态层、锁屏和错误层不能被普通应用 overlay 覆盖。
- 父对象删除导致的级联失效必须被组件和脚本句柄视为正常生命周期结果。
- Activity/Recent Apps/系统 overlay 管理的对象只能由对应 owner 释放；组件不得跨 owner 删除根对象。
- UI 和 SNI 回调必须快速返回，不得阻塞或从非 UI 线程直接操作 LVGL。
