# 脚本引擎概述

脚本引擎为 ElenixOS 应用和表盘提供 JavaScript 执行环境。它处理脚本包兼容性检查、模块加载、脚本程序生命周期和脚本可见 API 的资源管理。

## 引擎状态

当前引擎状态为：

| 状态 | 含义 |
|---|---|
| `UNINITIALIZED` | 尚未初始化 |
| `IDLE` | 已初始化但没有运行脚本 |
| `RUNNING` | 正在运行脚本 |
| `EXCEPTION` | 最近一次脚本执行进入异常状态 |

脚本程序管理器另外使用 `TERMINATED`、`STOPPING`、`ACTIVE` 和 `SUSPENDED` 表示程序生命周期。应用挂起时程序可以保持上下文，不能把 `SUSPENDED` 等同于 `TERMINATED`。

## 脚本包

应用和表盘统一使用 `.epk` 容器。运行时通过 EPK Header 的 Package Type 区分 Application 和 Watch Face，不从文件名或 manifest 推断类型。解析 manifest 时要求以下字段：

```text
id, name, version, author, description,
minApiLevel, targetApiLevel
```

`minApiLevel` 高于当前系统 API level 的应用会被拒绝启动。`permissions` 是可选数组，当前实现认识 `location`、`sensor`、`notification`、`storage`、`bluetooth`、`audio`、`health`、`contacts` 和 `calendar`；未知名字不会获得能力。

## 模块与上下文

每个运行中的脚本程序拥有自己的脚本上下文。相对或绝对模块路径会被规范化后加载并缓存；停止引擎时模块缓存被清除。脚本只能使用运行时挂载的 `eos` 与 `lv` 命名空间，不能把内部 C 类型或模块表当作公开 API。

## 资源和程序切换

LVGL 对象、timer、动画以及 ElenixOS Activity/View 句柄由运行时跟踪。应用挂起时，相关脚本回调资源会暂停，程序上下文和页面可被 Recent Apps 保留；应用恢复时再按系统策略恢复。完整停止或脚本致命错误会释放上下文及其资源。

Recent Apps 当前默认最多保留 3 个应用，并使用 2.5 MiB 内存水位作为驱逐条件；这些值可由 Kconfig 修改。被驱逐的应用会完整停止，而不是仅从 Recent Apps 列表删除。

## 执行超时

引擎默认使用 3000 ms 的执行超时。超时检测用于发现长时间无响应的脚本；应用不应通过设置一个很大的超时来替代拆分阻塞工作。超时、脚本异常和引擎崩溃属于不同的运行时故障类别。
