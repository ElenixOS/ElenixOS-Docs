# SNI 与资源生命周期

SNI 是脚本 API 与原生对象之间的桥接层。脚本看到的是由 `lv` 或 `eos` 返回的句柄，调用 API 时运行时把句柄解析为当前脚本上下文中的原生对象，并在返回值处重新生成受管理句柄。

## 可见命名空间

每个脚本上下文挂载两个命名空间：

- `lv`：LVGL 对象、控件以及 timer、anim 等脚本资源。
- `eos`：Activity、View、配置、时间、传感器、权限和系统 UI 等 ElenixOS API。

SNI 并不把所有 C 函数自动暴露给脚本；只有已注册的类、方法、属性和常量才是脚本接口。

## 句柄有效期

句柄的有效期受两个条件共同限制：脚本上下文仍然存在，且句柄对应的原生对象仍然存在。以下情况后不能继续使用旧句柄：

- 所属 Activity 或 View 被销毁；
- LVGL 父对象删除导致对象树级联删除；
- 脚本程序被完整停止、卸载或引擎复位；
- 脚本对象对应的原生资源被系统功能替换。

由 Activity 管理的 View 和页面对象不应绕过 Activity 生命周期直接删除。脚本创建的可删除资源应按相应 API 提供的删除方式释放；删除后不要保存或再次传递原句柄。

## 回调与暂停

SNI 回调仍然运行在脚本程序的事件循环中。回调应短小且不能阻塞。应用挂起时，属于该程序的 timer、动画和其他脚本回调资源会暂停；恢复时按 Recent Apps 的 timer/动画恢复策略继续、跳过或跳到结束状态。

## 参数与异常

脚本 API 会检查参数数量、类型和句柄类别。参数不符合方法要求时会抛出 JS 异常，调用方应根据公开方法签名传值，而不要依赖底层指针或内部句柄编号。原生对象已经失效时，相关方法同样不能继续使用。

## API 导出边界

原生绑定以类描述、方法描述、属性描述、常量和构造方式注册。静态类（例如 `eos.view`、`eos.config`）通过命名空间方法使用；可构造类（例如部分 `lv` 对象）通过 `new` 创建。注册表是实现细节，脚本只应依赖[JS API 文档](../elenix_os)和各控件页面列出的名称。
