# 运行时

运行时把平台初始化、系统服务、Activity 页面和脚本程序组合起来。它不是一个“脚本调用 C 函数”的薄封装，而是程序、Realm、页面和原生资源的生命周期协调层。

## 运行时模型

启动时先建立平台显示/输入和设备注册，再初始化系统服务，最后启动根 Activity、脚本运行时和应用/表盘。平台能力不足时由设备状态、能力查询或服务返回码向上表达；启动流程不得假设所有平台都提供相同能力。

脚本程序、Activity 和 View 是三个不同的所有权层次：

- SPM 拥有脚本程序、JavaScript Realm、SNI context 和脚本回调。
- Activity 控制器拥有页面栈、根 Activity、页面 View 和过渡。
- LVGL 拥有对象树中的子控件；父对象删除可能级联删除它们。

SPM 是脚本程序生命周期的唯一入口。上层应用/表盘管理器**禁止直接调用 `script_engine` 启动应用或表盘**，不能绕过 SPM 操作 Script Engine Core；启动、恢复、挂起和停止都必须通过 SPM 的应用/表盘管理接口完成。一个应用 ID 只允许一个未终止程序实例；实例 ID 将程序、Activity 和 Recent Apps 记录关联起来。

## 程序与页面状态

程序状态为 `ACTIVE`、`SUSPENDED`、`STOPPING` 或 `TERMINATED`。挂起表示程序仍可恢复，通常保留 Realm、页面子栈和 Recent Apps 快照；驱逐、卸载、根表盘替换或致命引擎错误才进入完整停止。

Activity 使用自己的页面状态和退出策略。页面过渡明确选择保留、销毁或停放，而不是让调用方修改一个长期存在的 destroy/suspend 标志。普通 Activity 不能由任意调用方直接销毁；根 Activity 由根替换流程管理。

## 回调、运行上下文与引擎复位

SNI 回调记录 owner program 和 engine generation。进入回调前必须确认程序仍为活动状态、上下文未暂停且 generation 未变化；调用 JS 前进入 owner Realm。LVGL 对象删除或引擎复位后，旧 callback、旧句柄和旧 native pointer 都失效。

引擎致命错误会保存错误上下文，清理受影响的程序和最近应用条目，并重建运行时。该事件表示系统已进入恢复路径；旧页面、View 和 JS 对象随原运行时失效，不能作为可恢复资源继续使用。

## 线程与调用约束

运行时主循环执行 Activity/LVGL 操作、LVGL timer 以及由这些 timer 派发的 SNI/JS 回调。新应用启动的 `main.js` 由 SPM 同步执行，会占用发起启动的主循环调用，加载界面不会让脚本并行运行。

Event Bus 本身不切换线程或排队：`eos_event_post` 在发布者上下文同步调用订阅者。Sensor `eos_sensor_notify` 也在发布者上下文同步调用 Native subscriber；Battery 数据变化会在 `eos_battery_report_raw` 调用栈同步发出事件。它们不能一概视作 GUI 主循环回调。平台 ISR/设备线程若要触发可能访问 LVGL、文件系统或脚本的链路，应先通过 Dispatcher 或目标 Service 的线程安全入口延后到适当上下文；跨线程传递的数据必须在排队前复制或保持有效。

即使回调由 timer/Dispatcher 派发，它也仍在 Core 调用栈中同步执行，应短小、非阻塞。只有 callback 的明确调度边界才能说明它运行在哪个上下文，不能从 `callback` 名称推断异步或线程安全。

## 运行时约束

- Activity/View 被销毁后，所有相关 C 指针和脚本句柄都必须视为失效。
- 脚本资源释放必须由所属 SPM/SNI context 完成；应用不能凭借 JS 引用计数绕过系统资源生命周期。
- 程序挂起时，其 timer、动画和脚本回调按 Recent Apps 的恢复策略暂停或恢复；挂起状态下不会继续执行任意 JS。
- 新增回调必须绑定明确的 owner、generation 和取消/删除路径，不能从全局 current-program 猜测归属。
