# 应用管理模块

应用管理模块负责已安装应用的发现、安装、卸载、排序和启动。脚本应用通过统一的 `.epk` 容器分发，运行时从包的 manifest 读取 ID、名称、版本、API level 和权限声明；Application/Watch Face 的安装分派由 EPK Header 的 Package Type 决定。

## 安装与卸载

应用安装会校验包和 manifest，并把应用文件部署到应用安装目录。安装一个已经存在的应用 ID 时，当前实现会替换原安装内容；应用 ID 是运行时识别应用的稳定键。

卸载会删除应用安装内容、应用数据和该应用的权限记录，并发布 `EOS_EVENT_APP_UNINSTALLED`。安装成功后发布 `EOS_EVENT_APP_INSTALLED`。调用方应检查 `eos_result_t`，不能在失败时假定目录或列表已经更新。

## 列表与排序

应用列表按已安装目录重新发现；已安装应用的存在不会依赖一个单独持久化的应用清单。应用排序顺序通过 `app_order` 配置保存，因此卸载或重新安装后，已不存在的 ID 不应继续作为有效排序项。

应用管理提供数量、按索引读取 ID、存在性判断和移动排序项等接口。应用管理本身不负责创建 Activity；启动时由 Activity、脚本程序管理器和应用列表协作完成。

## 运行生命周期

应用进入前台时创建或恢复 App Activity 和脚本程序。切换到其他可挂起应用时，当前应用进入 `SUSPENDED`，页面和脚本上下文可由 Recent Apps 保留；恢复时重新附加页面并继续运行。应用被用户关闭、卸载、Recent Apps 驱逐或引擎复位时，才进入完整停止状态并释放脚本资源。

应用不能把挂起当作退出：需要暂停的传感器、音频、timer 或动画工作应在相应生命周期中暂停，并在恢复时重新建立或校验状态。

## 包约束

运行时 manifest 需要 `id`、`name`、`version`、`author`、`description`、`minApiLevel` 和 `targetApiLevel`。`minApiLevel` 不兼容时应用不会启动。当前可声明的权限名见[脚本包与 JS API](../../script_engine)。
