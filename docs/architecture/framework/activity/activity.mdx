# Activity 页面

Activity 是页面生命周期和页面切换的唯一抽象。它描述页面在根 Activity、普通页面栈和停放应用子栈中的关系；它不是脚本程序的替代物。

## Activity 模型

当前 Activity 类型包括普通应用页、输入页、应用列表、当前表盘、表盘列表、锁屏、Recent Apps 和 Native App Debugger。App Debugger 是独立的工具页面类型，不是系统 App List 的别名。

系统有一个单独管理的根 Activity，通常是当前表盘。普通 Activity 进入页面栈；返回时由 Activity 控制器选择前一页面并处理当前页面的退出策略。一个 Activity 通常拥有一个 View，View 是其 LVGL 页面根对象。

## 根页面与页面栈

根 Activity 不由普通 `back` 操作销毁。表盘切换使用根替换流程，旧根及其 View/脚本资源随替换销毁，新根成为系统新的底层页面。应用和系统页面可以压入普通栈；应用的子页面还可以作为一个整体由 Recent Apps 停放和恢复。

页面返回、打开新页面和恢复 Recent Apps 都必须通过 Activity 控制器完成。调用方不应直接改变 Activity 栈链或把停放 View 重新挂到任意父对象。

## 生命周期与退出策略

Activity 生命周期包括进入、暂停、恢复和销毁：

- 进入时建立页面首次使用的 View 和内容。
- 暂停表示页面离开前台但仍可能恢复，不等于销毁。
- 恢复表示同一 Activity 再次成为活动页面。
- 销毁后，View、页面资源和 Activity 本体均不可再用。

页面过渡明确选择 `KEEP`、`DESTROY` 或 `SUSPEND`。过渡完成前，旧页面仍可能被动画快照或返回动画引用；清理必须由过渡收尾路径执行。停放的 Activity 不能使用普通直接销毁接口，驱逐时应通过 Recent Apps/按实例清理流程完成。

## 页面、脚本与对象所有权

Activity 拥有其页面 View；LVGL 父对象删除可能级联删除子控件。脚本程序拥有 Realm 和 SNI 资源，但不能因此越过 Activity 生命周期删除系统管理的 View。Activity 或 View 被销毁后，C 指针、脚本句柄和回调都必须视为失效。

页面切换完成后会同步发布系统事件。事件中的 View 指针仅在发布者保证的生命周期内有效，订阅者不会因此取得该 View 的所有权。

## 架构约束

- Activity 生命周期只能由 Activity 控制器及所属管理器驱动。
- 直接销毁只适用于不在栈中、不可见且未停放的 Activity；当前页面、根页面和最近应用页面必须使用其专用流程。
- Activity 的 View 只能在允许的 enter 流程中设置；运行中的页面不得随意替换或删除系统管理的 View。
- 页面过渡不能依赖调用方留下的 destroy/suspend 标志；退出语义必须属于当前 transition。
- App Debugger 必须保持独立 Activity 类型，不能复用 App List 的动画和业务路由。
- 根页面应通过 root Activity 语义访问；旧的 watchface getter 只保留兼容用途，不是新代码的推荐边界。

## 生命周期流转

应用启动：应用管理器 → SPM 创建/恢复程序 → Activity 创建应用页面 → 进入页面并建立 View → SNI/应用更新 UI。

应用离开前台：Activity 计算退出策略 → 完成页面过渡和栈分离 → Recent Apps 停放或驱逐 → SPM 挂起或停止对应程序。

表盘切换：表盘管理器 → 校验目标包 → 替换根 Activity → 停止旧表盘程序/资源 → enter 新根页面。

应用视角的启动、挂起与异步资源边界见[Application 契约](../../application_contract)；跨 Activity/SPM/SNI 的 owner 规则见[Core 开发契约](../../core_development_contract)。
