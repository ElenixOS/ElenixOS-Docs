# 日志服务

日志服务按严重级别过滤并向已注册的监听器派发格式化消息。系统提供调试、信息、警告和错误四个级别；全局最低级别决定哪些消息会被派发。

监听器由注册方负责生命周期。系统监听器不可按普通监听器注销；停用监听器不会删除注册关系。监听器回调应尽快返回，消息缓冲区只在派发期间有效，需长期保存时由接收方复制。

日志标签用于标识消息来源。平台可以提供标准输出等监听器；是否启用颜色输出由构建配置决定。

Core 日志级别启动时默认是 `DEBUG`，因此 DEBUG、INFO、WARN、ERROR 均可通过级别过滤。Simulator 项目默认启用 stdout listener，Native 启动日志也写入 Simulator 的 `tmp/latest.log`；目标平台若未注册输出 listener，日志仍会被级别过滤，但不会自动写入串口或文件。Simulator 最多接受 8 个 listener；槽位用尽时 `eos_log_register_listener()` 返回 `-1`。`EOS_LOG_ENABLE_STD`、`EOS_LOG_MAX_LISTENERS` 与 `EOS_LOG_USE_COLOR` 可通过 Kconfig 的 Logging 组调整；运行时也可用日志 API 更改最低级别。

Core 先按全局级别过滤，再同步调用监听器；listener 接收的消息内存仅在 callback 期间有效。平台输出 backend 是日志 listener，不是应用存储或通知服务。若 sink 需要耗时 I/O，应在 listener 中复制所需内容并自行排队；见[事件总线的上下文区别](../../kernel/event/events)。
