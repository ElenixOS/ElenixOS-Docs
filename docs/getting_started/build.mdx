# 板级固件构建路径

板级固件由目标 Platform / BSP 工程构建。ElenixOS Core 不提供一条适用于所有 SoC 和 Board 的通用固件命令：SDK、交叉编译器、配置、启动镜像布局和下载方式都由具体板级工程决定。本页帮助 Platform / BSP 开发者选择对应工程和后续说明。

## 当前集成工程

| 目标 | 状态 | 后续步骤 |
|---|---|---|
| PSoC Edge E84 系列 | 开发中，尚未形成稳定移植。 | 查看 [E84 开发工程构建与烧录](../integration/psoc_edge_e84_build)，再按工程说明选择目标板和连接方式。 |
| 自有 SoC / Board | 由移植工程定义。 | 从[Platform 与 Board 集成](../integration/overview)和 [Platform / Vendor 契约](../architecture/platform_contract)开始，建立目标工程后使用其构建、配置和下载流程。 |

## 区分目标和产物

- **板级固件**：由 Platform / BSP 工程为目标芯片和板卡构建，再使用该工程的下载器烧录。
- **Application / Watch Face 安装包**：由应用开发路径构建为 `.epk`，安装到已经运行 ElenixOS 的系统；它不是固件镜像。项目流程见[Application 开发](./application_development)和 [Watch Face 开发](./watchface_development)。
- **Simulator 桌面程序**：由独立的 Simulator 工程构建，用于桌面迭代，不是板级固件目标。命令和运行方式见[Simulator 构建与运行](../simulator/build)。

每个 Platform / Board 工程应说明自身的先决条件、目标选择、配置入口、构建产物和烧录步骤。Core 编译期选项由 Kconfig 管理，具体项目默认值仍由板级工程决定；配置入口见[内核配置系统](../development/kconfig)。移植时的 Core 边界与设备注册约束见 [Platform / Vendor 契约](../architecture/platform_contract)；系统内各层关系见[系统架构](../architecture/arch)。
