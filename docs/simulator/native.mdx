# Native Simulator 运行模型与调试

Native 模拟器把 ElenixOS 编译为主机上的桌面程序。普通模式通过 SDL2 提供显示和输入；headless 模式不创建 SDL 窗口，而是把 LVGL framebuffer 送到本地 WebSocket/IPC 传输，并把输入回送到同一条 Simulator/LVGL 主循环。

本页只适用于桌面 Native 目标。板级固件由 Board / Platform 工程构建和烧录，入口见[Platform 与 Board 集成](../integration/overview)和[板级固件构建路径](../getting_started/build)；Simulator 的适用范围和限制见[模拟器概述](./overview)。

## 启动与运行行为

Native 的配置、完整构建命令和 `bin/main` 启动步骤见[Simulator 构建与运行](./build)。本页聚焦 Native 窗口、输入以及 headless 调试边界。

## 运行时交互

模拟屏幕固定为 390×450 像素。Native 窗口提供表冠和侧边按钮的模拟控件；表冠还可通过鼠标滚轮模拟编码器旋转。短按表冠和侧边按钮会产生各自的点击输入，长按表冠会产生长按输入。

窗口可调整大小，最小尺寸由模拟器设置；调整窗口大小只改变桌面显示，不改变系统显示尺寸。headless 模式仍使用 390×450 的逻辑显示尺寸，WebSocket 端点和认证 token 通过启动握手 marker 提供给调试前端。

## Headless 控制面

Native headless 可以这样启动：

```bash
./bin/main --headless --ipc-socket /tmp/elenixos-simulator.sock
```

WebSocket 负责单个 loopback Webview 的帧和触摸/按键/表冠输入；本地 IPC 负责启动握手、兼容控制和退出状态。两个传输都使用非阻塞轮询，输入必须在 Simulator 主线程注入；它们不是给应用使用的通用 IPC。

传输只保留最新的完整 RGB565 帧，不能假设存在 dirty rectangle、压缩图像或多客户端广播。ESH 仍是 Native 的诊断/控制通道，与 framebuffer WebSocket 分离；使用 ESH 的命令前应先确认当前构建实际注册的命令。

## 调试配置

ASAN、FreeRTOS、绘制后端、图片格式、FFmpeg 和 FreeType 通过 Simulator 构建选项控制；完整参数和命令见[Simulator 构建与运行](./build)。可移植 Core 的 Kconfig 配置见[内核配置系统](../development/kconfig)。

## 架构边界

- SDL、headless display 和 WASM 页面是平台显示端口，不改变 ElenixOS 的 Activity、服务和脚本模型。
- ESH、WebSocket 和 IPC 是观测/控制边界，不能替代板卡上的 UI 截图、交互或硬件验证。
- 平台输入必须进入统一输入适配层；调试前端不得直接修改 LVGL 对象或 Activity 状态。

Native 构建需要 SDL2 开发库，主机依赖见[Simulator 环境准备](../getting_started/environment)。
