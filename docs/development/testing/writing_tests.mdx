# 编写测试

## 选择测试形式

对确定的 API 结果、边界条件和错误路径进行回归验证时，使用同步测试框架。需要持续渲染、用户操作、真实时间流逝或硬件反馈时，使用测试应用中的独立 GUI 页面。

## 同步测试契约

测试函数在 LVGL 主循环上下文中调用，必须在返回前完成验证并记录结果。不要在测试中阻塞等待，也不要把“测试已启动”当作通过；跨帧场景应改写为可在一次调用中检查的条件，或使用独立交互式页面。

测试结果记录以框架当前的记录规则为准。一次执行后，后续异步回调不能可靠地覆盖已经完成的测试结果。

## 命名和注册

测试名必须唯一。当前 GUI 会按名称中的前缀分组；保持同一组测试使用一致的前缀即可归入同组。注册应在测试页面创建之前完成，并通过对应子系统的测试注册入口加入 runner。

## 资源清理

测试创建的 Activity、LVGL 对象、timer、订阅和文件应在测试结束或页面销毁时清理。Activity/View 删除可能级联删除子对象，测试不应在删除后继续使用旧指针。需要多次运行的测试还应把全局状态恢复到可重复的初始条件。

## 交互式页面

UI、传感器、音频等无法在一次同步调用中判定的场景，可创建独立 Activity 页面，由页面生命周期管理对象和订阅。独立页面负责展示结果，不会自动加入框架层的通过/失败聚合。

## 容量与配置

测试应用由 `EOS_ENABLE_TEST_APP` 控制。测试条目和分组数量存在编译期限制；接近上限时应合并重复场景或调整构建配置，而不是假设注册表会动态扩容。
