# Testing Overview

The current test application is built on top of the LVGL runtime, providing interactive test pages and a synchronous test framework. It is not a standalone headless command-line test program.

## Test Framework

Tests are registered by name and function into a fixed-capacity test table. The runner can execute all or a subset of tests based on selection, and displays results in the GUI page and logs. Duplicate names do not create a second test; tests exceeding the compile-time capacity are not added.

Test functions execute synchronously within the current call, using the framework-provided recording/assertion interfaces to write results. After a test returns, the runner proceeds to the next selected test; the current implementation has no general asynchronous protocol for suspending a test across multiple LVGL ticks before settling.

## GUI Page

The test application provides a test list, group selection, run progress, and result display. Features that require continuous observation or manual operation (such as UI, sensors, and audio) should use separate interactive pages; the results of such pages are not automatically counted in the synchronous test framework's statistics.

## Compile-Time Switch

The test application is controlled by `EOS_ENABLE_TEST_APP`. When this configuration is disabled, test application-related code is not included in the build. When enabled, tests still require full LVGL/system runtime initialization.

## Current Limitations

- There is no standalone headless runner; a set of tests cannot be run in a pure console environment using only the test framework API.
- Test functions must complete verification before returning; they cannot rely on asynchronous callbacks to change already-recorded results.
- Tests and groups use fixed capacity, with specific limits determined by the current test framework's compile configuration.
- Test registration should be completed before test pages are created, otherwise new entries will not appear in an already-built list.
