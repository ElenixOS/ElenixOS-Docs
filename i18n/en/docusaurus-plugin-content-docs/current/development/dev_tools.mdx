# Simulator Build Tools and Logging

This page describes the CMake / Makefile, Kconfig, and Native logging entry points in the ElenixOS-Simulator repository. These are host-side tools for the desktop Simulator, not a unified build interface for each Board's firmware. Application / Watch Face projects, EPKG builds, and analysis are handled by [ElenixOS-Toolkit](./toolkit); board-level firmware is built according to [Platform and Board Integration](../integration/overview) and the documentation of the corresponding project.

## Build and Configuration

```bash
cmake -S . -B build
cmake --build build --parallel
cmake --build build --target menuconfig
```

`menuconfig` uses `kconfiglib` to generate the `.config` and generated configuration header in the build directory. For the configuration override order and available options, see [Kernel Configuration System](./kconfig).

## Application / Watchface Development

Project initialization, EPKG package building, and analysis of existing packages are provided by the official VS Code extension [ElenixOS-Toolkit](./toolkit). The package format itself is defined by [EPKG v1 Package Format](../architecture/package_format).

The `ElenixOS/scripts/eos_pkg_builder.py` in the simulator repository is the legacy standalone packaging tool, currently in a deprecated / legacy state, and is no longer the recommended build entry point for new Application or Watchface projects.

## Running and Logging

The Native build artifact is `bin/main` in the repository root; runtime logs are written to `tmp/latest.log` and archived by time. The WASM build artifact is in the build directory's `bin/`, and requires an HTTP server to serve it to the browser.

The repository does not have the generic `build.sh`, `clean.sh`, `eos_log_i`, and other tool interfaces referred to as legacy in the documentation; for logging, use `EOS_LOG_D/I/W/E` or the script-side `eos.console.*`.
