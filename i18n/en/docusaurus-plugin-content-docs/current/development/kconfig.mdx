# Kernel Configuration System

ElenixOS manages compile-time kernel configuration via Kconfig. Final effective values are determined by two independent merge stages: the Kconfig merge layer and the C preprocessor layer.

## Kconfig Merge Layer

The script `kconfig.py genconfig` merges the following three layers using `replace=True` — **later values overwrite earlier ones**:

1. Kconfig built-in `default` statements — kernel-defined baseline defaults
2. Project `defaults.conf` — establishes the baseline for the current platform/product; the Simulator's file is located at `main/src/config/defaults.conf`
3. Build directory `.config` — local `menuconfig` modifications stored in the build directory, with the highest priority

The merge output is written to `build/generated/eos_config_gen.h`. Each value maps one-to-one to its native macro name, emitted under an `#ifndef` guard.

## C Preprocessor Layer

The header `eos_config.h` includes configuration definitions in a fixed order, with all symbols guarded by `#ifndef` — **first definition wins**:

1. Compiler `-D` flags
2. `eos_platform_config.h` — manual platform overrides (optional)
3. `eos_config_gen.h` — Kconfig merge output (optional, auto-generated by the build)
4. `eos_config_defaults.h` — kernel fallback defaults

Any stage can prevent subsequent stages from taking effect, forming a complete override chain from the build command line down to the kernel fallback. For example, the Simulator's Native CMake configuration sets the `EOS_SYS_ROOT_DIR` compile macro to the repository's `fs/` directory, taking precedence over the `/` default in Kconfig.

## Common Simulator Defaults

The table below lists the defaults currently used by the Simulator project's `main/src/config/defaults.conf` that affect day-to-day development or operation. They represent the Simulator baseline when not overridden by the local build directory's `.config`; other BSPs may have different project defaults.

| Kconfig Item | Simulator Default | Impact and Adjustment Entry Point |
|---|---:|---|
| `EOSCFG_COMPILE_MODE_DEBUG` | Enabled | Core runs in Debug compile mode; can be switched to Release in `menuconfig` under Build & Compilation. |
| `EOSCFG_MEM_STDLIB` / `EOS_OVERRIDE_LVGL_STDLIB_MALLOC_ENABLE` | Enabled / Disabled | Core uses the C standard allocator by default; the Simulator does not replace LVGL's stdlib allocator with the EOS allocator by default. Can be switched in the Memory menu. |
| `EOS_MEM_TRACK_ENABLE` / `EOS_MEM_TRACK_TABLE_SIZE` | Configured as Enabled / 4096 entries | These two symbols currently have no Core source consumers, so modifying them will not enable/disable or limit the current allocation tracking; `eos_mem.c` currently records allocation statistics independently. |
| `EOS_CACHE_ENABLE` / `EOS_CACHE_SIZE` / `EOS_CACHE_HEADER_COUNT` / `EOS_CACHE_USE_DEDICATED_MEM` | Enabled / 524288 bytes / 16 entries / Disabled | The LVGL image decode cache budget is 512 KiB, with up to 16 cache header records; the Simulator does not use a dedicated cache memory pool. The budget and count can be adjusted in the Image cache menu. The kernel Kconfig original budget is 393216 bytes, and the Simulator project overrides it to 524288 bytes by default. |
| `EOSCFG_FONT_TTF` / `EOSCFG_FONT_TTF_FILE` | Enabled / Enabled | Loads TrueType fonts from the filesystem by default; `EOS_FONT_TTF_FILE_PATH` is `font.ttf`, relative to the system font resource directory. Large/medium/small fonts default to 30/26/22 px. The font source, path, and size can be changed in the Font menu. |
| `EOS_DISPLAY_WIDTH` / `EOS_DISPLAY_HEIGHT` / `EOS_DISPLAY_RADIUS` | 390 / 450 / 80 px | Default simulated screen geometry; window scaling does not rewrite system display coordinates. Target panel parameters can be set in the Display menu. The brightness configuration range defaults to 5–100. |
| `EOSCFG_FS_POSIX` / `EOS_FS_PATH_MAX` / `EOS_LVGL_FS_LETTER` | POSIX / 256 bytes / `Z` | Default filesystem interface, path buffer limit, and LVGL file drive letter. The configured value `90` corresponds to drive letter `Z`, which must match LVGL's `LV_FS_DEFAULT_DRIVE_LETTER`. Can be adjusted in the File system menu. |
| `EOSCFG_LANG_EN` | Enabled | The Simulator's default UI language on first launch is English; can be changed to Simplified Chinese in the Language menu. |
| `EOS_USE_ASSERT` / `EOS_LOG_ENABLE_STD` / `EOS_LOG_MAX_LISTENERS` / `EOS_LOG_USE_COLOR` | Enabled / Enabled / 8 / Disabled | Assertions and the stdout log listener are enabled by default, with up to 8 log listeners registered; the minimum log level is managed by the runtime logging service, with an initial value of `DEBUG`. Registration returns `-1` when the listener table is full. The Logging menu controls assertions, the stdout listener, capacity, and color output. |
| `EOS_RECENT_APPS_ENABLE` / `EOS_RECENT_APPS_MAX` / `EOS_RECENT_APPS_MEM_HIGH_WATERMARK` | Enabled / 3 / 2621440 bytes | Retains up to 3 suspended apps, with an estimated memory high watermark of 2.5 MiB; evicts by LRU once the limit is reached. Timer recovery re-issues one missed callback by default, and animations resume from the pause point. Can be adjusted in the Recent Apps menu. |
| `EOS_ENABLE_TEST_APP` | Enabled | Includes the built-in test app in the Simulator; can be disabled in the Miscellaneous menu. |

The `.config` in the local build directory overrides the Simulator defaults in the table. To confirm the final configuration of a specific build, check the `.config` and `generated/eos_config_gen.h` in that directory; CMake `-D` arguments and platform configuration macros may also override the generated values during the preprocessing stage.

## Operations

The project root `Makefile` provides the following targets:

| Target | Action |
|--------|--------|
| `make` / `make build` | Build the already-configured `build/` directory |
| `make menuconfig` | Edit `build/.config` and refresh that build directory's `generated/eos_config_gen.h` (`cmake -B build && cmake --build build --target menuconfig`) |
| `make run` | Build and run |

### Dependency Installation

```bash
pip install kconfiglib
```

### Multiple Build Directories

`.config` files are fully isolated per build directory. Native and WASM builds can hold independent configurations:

```bash
# Native
cmake -B build
make menuconfig        # Edit build/.config

# WASM
cmake -B build-wasm -D EOS_PLATFORM=WASM
cmake --build build-wasm --target menuconfig    # Edit build-wasm/.config
```

:::note
`menuconfig` requires terminal curses support. On Windows, use MSYS2 terminal.
:::

## Boundary with CMake Options

CMake options (such as `EOS_PLATFORM`, `USE_FREERTOS`, and optional LVGL backends) control the platform, dependencies, compilation units, and linking behavior. Kconfig manages compile-time configuration macros such as memory strategy, filesystem type, fonts, logging, and Recent Apps. The two have different entry points, but CMake `-D` compile definitions may take precedence over Kconfig macros of the same name; the Simulator's `EOS_SYS_ROOT_DIR` is a real example. Running `menuconfig` saves `.config` and updates the generated header of the configured build directory; after directly editing `.config`, re-run `cmake -B build`.

## CI Behavior

GitHub Actions executes `pip install -r requirements.txt` before the build step. CMake configuration auto-completes Kconfig merge and header generation. Should `genconfig` fail, the build proceeds, falling back to `eos_config_defaults.h`.

## Fallback Mechanism

When Kconfig is not installed or `genconfig` fails, the kernel falls back to `eos_config_defaults.h`. The minimal flow `cmake -B build && cmake --build build` remains available under all conditions.
