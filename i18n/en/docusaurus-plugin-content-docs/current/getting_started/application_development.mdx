# Application Development Tutorial

This tutorial creates a script Application that displays "Hello, ElenixOS!", builds an EPKG installation package, and installs and launches it on the Native Simulator or a board running ElenixOS. An application package is not device firmware; board-level firmware is built and flashed by the target Platform / Board project.

## Prerequisites

- Visual Studio Code 1.136 or later is installed on the host.
- [ElenixOS-Toolkit](../development/toolkit)has been searched for and installed from the VS Code Extensions, or`code --install-extension ElenixOS.elenixos-toolkit`has been executed in a terminal with the`code`command installed.
- There is a target system that has been built and is running: the Native Simulator, or a board that provides ESH, YMODEM receive, and the EPKG Installer. For the Simulator's host dependencies and build steps, see [Environment Preparation](./environment)and [Simulator Build and Run](../simulator/build). For board-level firmware paths, see [Board-Level Firmware Build Paths](./build).

The following paths use`$HOME`and bash/zsh commands. Windows users can use the MSYS2/MinGW shell supported by the project, or complete project and package builds through the VS Code graphical interface.

## 1. Create an Application Project

Create the project parent directory in the host terminal:```bash
mkdir -p "$HOME/ElenixOS-Apps"
```Run **ElenixOS: Open App Tools** in the VS Code command palette, enter the **Create** workspace, and fill in the following information:

| Field | Example Value |
|---|---|
| App name |`Hello ElenixOS`|
| App ID |`com.example.hello`|
| Version |`1.0.0`|
| Author |`Example`|
| Description |`A first ElenixOS application`|
| Project location |`$HOME/ElenixOS-Apps`|

Select **Create App project**. This App ID should not already exist under`$HOME/ElenixOS-Apps/`. The Toolkit will create`$HOME/ElenixOS-Apps/com.example.hello/`, which contains the root-level`manifest.json`and the entry script`main.js`.

## 2. Write the Entry Script

Open`$HOME/ElenixOS-Apps/com.example.hello/main.js`, replace the default entry comment with the page code below, and save:```js
const view = eos.view.active();
const button = new lv.button(view);
button.align(lv.ALIGN_CENTER, 0, 0);

const label = new lv.label(button);
label.setText("Hello, ElenixOS!");
```The`id`in`manifest.json`is the stable identity used during installation and at runtime. The fields generated by the Toolkit can be used directly for this example; for the required fields of EPKG v1 and the semantics of API level, see [Installation Package Format](../architecture/package_format). For the Program, Activity, View, and SNI lifecycles of an Application, see [Application and Framework Contract](../architecture/application_contract).

## 3. Build and Validate the Installation Package

First create the output directory:```bash
mkdir -p "$HOME/ElenixOS-Apps/build"
```In the **Build** workspace of App Package Studio, select **Select App project** and open`$HOME/ElenixOS-Apps/com.example.hello/`. Choose **Application** for Package type and click **Validate project**; after validation passes, click **Build package** and save the output as`$HOME/ElenixOS-Apps/build/hello.epk`. After the build completes, the Toolkit displays the package path; the **Analyze** workspace can be used to view the package identity, type, and file table.

For automated builds, the`etk`CLI can be used. Installing the Marketplace extension is not equivalent to having the`etk`command already available in the host`PATH`; for how to build and install the CLI, see [Toolkit Documentation](../development/toolkit). In a terminal that already has the`etk`command, execute:```bash
etk package build "$HOME/ElenixOS-Apps/com.example.hello" \
  --output "$HOME/ElenixOS-Apps/build/hello.epk" --type app --compression auto
etk validate "$HOME/ElenixOS-Apps/build/hello.epk"
```A complete validation should show EPKG v1, package ID`com.example.hello`, and`Validation: full`.`inspect`is a structural preview and does not replace full payload validation.

## 4. Install and Launch

Choose one deployment path that corresponds to the current running target.

### Run on the Native Simulator

First generate the Native program according to [Simulator Build and Run](../simulator/build). The following commands are executed from the root directory of the`ElenixOS-Simulator`repository:```bash
mkdir -p fs/tmp
cp "$HOME/ElenixOS-Apps/build/hello.epk" fs/tmp/hello.epk
./bin/main
```After the Simulator starts, execute the following one by one at the ESH prompt in the same terminal:```text
pkg validate /tmp/hello.epk
pkg install /tmp/hello.epk
apps
app start com.example.hello
````pkg validate`should return`pkg: valid EPKG v1`, and`apps`should list`com.example.hello`. After launching, the simulated screen displays a centered **Hello, ElenixOS!** button.

### Install on a Running Board

The target firmware needs to register ESH's YMODEM receive,`pkg validate`,`pkg install`, and Application management capabilities. Run **ElenixOS: Open ESH Terminal** in the VS Code command palette and select the device UART. The Toolkit's default serial format is 8N1, with RTS/CTS flow control disabled, and`elenixosToolkit.uartBaudRate`defaults to`921600`; the host rate must match the device side, and this configuration item can be modified in VS Code Settings.

Then run **ElenixOS: Send File or Folder with YMODEM (UART)**, select`$HOME/ElenixOS-Apps/build/hello.epk`, and set the device-side path to`/tmp/hello.epk`. After the transfer completes, execute in the ESH Terminal:```text
pkg validate /tmp/hello.epk
pkg install /tmp/hello.epk
```After complete validation succeeds and installation is done, open **Hello ElenixOS** from the target system's Application list. If the Board uses its own deployment tool or different ESH commands, defer to the corresponding Platform / Board project; the Simulator and the currently in-development E84 integration do not mean that all boards provide the same installation capabilities.
