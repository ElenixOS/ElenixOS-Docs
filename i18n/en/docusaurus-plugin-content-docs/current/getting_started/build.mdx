# Board-Level Firmware Build Path

Board-level firmware is built by the target Platform / BSP project. ElenixOS Core does not provide a universal firmware command that applies to all SoCs and Boards: the SDK, cross-compiler, configuration, boot image layout, and download method are all determined by the specific board-level project. This page helps Platform / BSP developers choose the corresponding project and follow-up documentation.

## Distinguish Targets and Artifacts

- **Board-level firmware**: Built by the Platform / BSP project for the target chip and board, then flashed using that project's downloader.
- **Application / Watch Face package**: Built via the application development path as a `.epk`, installed onto a system already running ElenixOS; it is not a firmware image. See [Application Development](./application_development) and [Watch Face Development](./watchface_development) for the project flow.
- **Simulator desktop program**: Built by the standalone Simulator project for desktop iteration; it is not a board-level firmware target. See [Simulator Build and Run](../simulator/build) for commands and how to run it.

Each Platform / Board project should document its own prerequisites, target selection, configuration entry points, build artifacts, and flashing steps. Core compile-time options are managed by Kconfig, while specific project defaults are still determined by the board-level project; see the [Kernel Configuration System](../development/kconfig) for configuration entry points. For Core boundaries and device registration constraints during porting, see the [Platform / Vendor Contract](../architecture/platform_contract); for the relationships between layers within the system, see [System Architecture](../architecture/arch).
