# Simulator Build and Run

This page only covers the desktop target of ElenixOS-Simulator. The Simulator builds ElenixOS Core on the host and runs it natively or via WASM; it is not a firmware build for a specific Board. When first obtaining the code, initialize the submodules:```bash
git clone --recursive https://github.com/ElenixOS/ElenixOS-Simulator.git
cd ElenixOS-Simulator
```For an existing workspace, run:```bash
git submodule update --init --recursive
```For Native dependencies, see [Simulator Environment Preparation](../getting_started/environment). To build board-level firmware, select the target Board from [Board-Level Firmware Build Paths](../getting_started/build).

## Native

The Native build requires the SDL2 development library. Build and run with Debug:```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build --parallel
./bin/main
```If`build/`is already configured, you can also use the root Makefile:```bash
make
make run
```The Native simulated screen is 390×450 pixels, and the window provides crown and side button input controls; resizing the window does not change the system's logical display size.

## WASM

The WASM build requires an activated Emscripten toolchain:```bash
emcmake cmake -S . -B build-wasm -DEOS_PLATFORM=WASM -DCMAKE_BUILD_TYPE=Release
cmake --build build-wasm --parallel
```The artifacts are located in`build-wasm/bin/`, including`main.html`,`main.js`,`main.wasm`, and preloaded data files. Access via an HTTP server:```bash
cd build-wasm/bin
python3 -m http.server 8000
```Then open [http://localhost:8000/main.html](http://localhost:8000/main.html); you cannot open it directly with`file://`.

## Build Options

| Option | Default | Purpose |
|---|---:|---|
|`EOS_PLATFORM`|`Native`| Select`Native`or`WASM`|
|`USE_FREERTOS`|`OFF`| Enable FreeRTOS under Native; disabled under WASM |
|`LV_USE_DRAW_SDL`|`OFF`| Enable the SDL drawing backend, requires the corresponding SDL2_image dependency |
|`LV_USE_LIBPNG`/`LV_USE_LIBJPEG_TURBO`|`OFF`| Enable PNG / JPEG decoding support |
|`LV_USE_FFMPEG`/`LV_USE_FREETYPE`|`OFF`| Enable FFmpeg / FreeType support |
|`ASAN`|`OFF`| Enable Address / Leak / Undefined sanitizer for Debug builds |

Optional backends can only be enabled when the dependency libraries can be found by CMake.

## Kconfig

Configurations such as memory policy, fonts, display parameters, logging, and Recent Apps are managed through Kconfig:```bash
cmake -B build
cmake --build build --target menuconfig
```The configuration is saved in the current build directory`.config`, and the generated header file is located in`build/generated/`. When`menuconfig`is saved,`generated/eos_config_gen.h`in that directory is refreshed at the same time; if you edit`.config`directly, first run`cmake -B build`to regenerate the configuration header file. For the complete priority and configuration values, see [Kernel Configuration System](../development/kconfig).

## Logging and Troubleshooting

Native currently writes logs to the Simulator repository`tmp/latest.log`, and old logs are archived by time. If SDL2 cannot be found during the configuration phase, install the SDL2 development package first; if submodules are missing or linking errors occur, confirm that recursive submodule update has been executed, then reconfigure using a new build directory.
