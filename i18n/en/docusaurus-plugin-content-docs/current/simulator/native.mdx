# Native Simulator Runtime Model and Debugging

The Native simulator compiles ElenixOS into a desktop program on the host. In normal mode, SDL2 provides display and input; in headless mode, no SDL window is created—instead, the LVGL framebuffer is sent to a local WebSocket/IPC transport, and input is fed back into the same Simulator/LVGL main loop.

This page applies only to the desktop Native target. Board-level firmware is built and flashed by the Board / Platform project; see [Platform and Board Integration](../integration/overview) and [Board-level Firmware Build Path](../getting_started/build) for entry points. For the applicable scope and limitations of the Simulator, see [Simulator Overview](./overview).

## Startup and Runtime Behavior

For Native configuration, complete build commands, and `bin/main` startup steps, see [Simulator Build and Run](./build). This page focuses on the Native window, input, and headless debugging boundaries.

## Runtime Interaction

The simulated screen is fixed at 390×450 pixels. The Native window provides simulated controls for the crown and side button; the crown can also be rotated via the mouse wheel to simulate encoder rotation. A short press of the crown and side button produces their respective click inputs, and a long press of the crown produces a long-press input.

The window is resizable, with the minimum size set by the simulator; resizing the window only changes the desktop display, not the system display size. Headless mode still uses a logical display size of 390×450, and the WebSocket endpoint and authentication token are provided to the debugging frontend via a startup handshake marker.

## Headless Control Plane

Native headless can be started as follows:

```bash
./bin/main --headless --ipc-socket /tmp/elenixos-simulator.sock
```

WebSocket handles frames and touch/key/crown input for a single loopback Webview; local IPC handles the startup handshake, compatibility control, and exit status. Both transports use non-blocking polling, and input must be injected on the Simulator main thread; they are not general-purpose IPC for applications.

The transport only retains the latest complete RGB565 frame, and you cannot assume the existence of dirty rectangles, compressed images, or multi-client broadcast. ESH remains the Native diagnostic/control channel, separate from the framebuffer WebSocket; before using ESH commands, first confirm which commands are actually registered in the current build.

## Debug Configuration

ASAN, FreeRTOS, drawing backend, image formats, FFmpeg, and FreeType are controlled via Simulator build options; for complete parameters and commands, see [Simulator Build and Run](./build). For Kconfig configuration of the portable Core, see [Kernel Configuration System](../development/kconfig).

## Architecture Boundaries

- SDL, headless display, and the WASM page are platform display ports and do not change ElenixOS's Activity, service, and script model.
- ESH, WebSocket, and IPC are observation/control boundaries and cannot replace UI screenshots, interaction, or hardware verification on the board.
- Platform input must enter the unified input adaptation layer; the debugging frontend must not directly modify LVGL objects or Activity state.

Building Native requires the SDL2 development library; for host dependencies, see [Simulator Environment Preparation](../getting_started/environment).
