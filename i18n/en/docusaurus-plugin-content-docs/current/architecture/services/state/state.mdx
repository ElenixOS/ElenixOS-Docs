# State Service

The state service stores system state that must persist across runtime instances, and is distinct from the configuration service: configuration describes adjustable settings, while state records data formed during operation, such as battery capacity information.

The service stores boolean, string, and numeric types by key, and writes state to the system state file. When reading a missing value, the caller provides a fallback value; dynamic strings and parsed JSON data are freed by the receiver according to its resource rules.

The persistence path is managed by the system storage configuration. Application scripts use isolated application configuration; the system state file is not part of the application script's configuration boundary.

The state service owns system persistent state keys and values; consumers pull the current value and handle defaults, and do not write the state file directly. Persistence capability depends on the Storage/platform filesystem port; state is not an event log or an application-private configuration space. See [Application Contract](../../application_contract) and [Storage Service](../storage).
