# Storage Service

The storage service provides common JSON, file, and directory operations over a platform file-system port. The port implements persistence for its target; the service accepts paths and handles and does not infer an application or script identity from them.

## Data and durability

Typed JSON helpers build on file operations and return caller-owned strings or parsed JSON values according to their allocation rules. Writes may use the optional Deferred File Writer; callers that need an immediate write use the synchronous path.

## Handles and platform boundary

Files and directories use explicit handles. A failed open returns an invalid handle, and a handle becomes unusable when closed. The platform port supplies the file-system implementation and may map a virtual system root to a host path. That mapping is a platform choice, not an application security boundary.

## Script paths and isolation

SNI helpers construct asset and configuration paths from the current application or watch-face identity. The generic storage API does not scope or rewrite paths based on the current script, so it is not an automatic per-application sandbox. Any JavaScript-facing file capability must enforce its path policy at its own API boundary before calling the storage service.

Deferred File Writer is an optional build-time capability.
