# Configuration Service

The configuration service manages system-level settings and persists them as JSON. Configuration items cover device and language, display and power, audio and haptics, watchface and app ordering, and security options. System modules access them through typed configuration and should not parse or rewrite the system configuration file themselves.

When reading a configuration item that is missing or has a type mismatch, the caller-provided default value is used. Dynamic strings and JSON trees are freed by the caller according to their respective resource rules. Development debug options may also be stored as ordinary configuration data and do not thereby become compile-time configuration.

Script configuration and system configuration are isolated from each other and are stored in the data directory of the corresponding app or watchface; system-level configuration is not part of the script configuration boundary.

The configuration service is a synchronous Core-owned settings snapshot, and when a key is missing the reader provides the default semantics; it is not a real-time device data subscription. JS `eos.config` writes to the corresponding app/watchface configuration location based on the current script identity, whereas the generic Storage API does not automatically apply this identity isolation. For the calling layer, see [Application Contract](../../application_contract).
