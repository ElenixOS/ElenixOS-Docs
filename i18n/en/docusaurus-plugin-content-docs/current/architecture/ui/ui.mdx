# UI Components Module

The UI components module is one of the core components of ElenixOS, providing a series of user interface components and interaction functions, built based on the LVGL graphics library. This module provides a unified UI components and interaction methods for applications, ensuring the consistency and aesthetics of the system interface.

## Core Features

### Basic Components

Basic components include buttons, labels, input fields and other basic UI elements, providing basic user interaction functions for applications.

### Advanced Components

Advanced components include card pagers, bubble grids, swipe panels and other complex UI elements, providing rich interaction methods for applications.

### Animation System

The animation system provides rich animation effects, including fade in/out, slide, scale, etc., enhancing the visual effects and interactive experience of the user interface.

### Activity Controller

The activity controller is responsible for managing the activity lifecycle of applications, including activity creation, switching, destruction, etc.

## Key Interfaces

### Standard Components Interfaces

```c
lv_obj_t *eos_std_info_create(lv_obj_t *scr,
                              lv_color_t icon_bg_color,
                              const char *icon,
                              const char *title_txt,
                              const char *txt);

void eos_std_title_comment_create(lv_obj_t *parent,
                                  const char *title,
                                  const char *comment);
```

- `eos_std_info_create`：Create message page, including icon, title and text
- `eos_std_title_comment_create`：Create title and comment combination

### Animation Interfaces

The animation system provides rich animation effect interfaces. For details, please refer to the `eos_anim.h` file.

### Activity Controller Interfaces

The activity controller provides activity management interfaces. For details, please refer to the `eos_activity.h` file.

## Implementation Details

The core implementation of the UI components module includes:

1. **Component encapsulation**：Encapsulate LVGL basic components to provide more advanced components and functions
2. **Style management**：Unified management of component styles to ensure consistent interface style
3. **Animation effects**：Implement various animation effects to enhance user experience
4. **Interaction processing**：Handle user input and interaction events

This module is based on the LVGL graphics library, providing rich UI components and interaction functions for ElenixOS.

## Usage Examples

### Create Message Page

```c
lv_obj_t *info_page = eos_std_info_create(lv_scr_act(),
                                         lv_color_hex(0x007AFF),

```

### Create Title and Comment

```c
eos_std_title_comment_create(parent,

                           "This is comment content");
```

## UI Architecture

The UI components module adopts a layered architecture:

1. **Basic component layer**：Based on LVGL-provided basic components
2. **Advanced component layer**：Encapsulate and extend basic components to provide more advanced functions
3. **Application component layer**：Components for specific application scenarios

This architectural design allows UI components to maintain consistent style and interaction methods across different application scenarios, while providing sufficient flexibility and scalability.

## UI Ownership and Extension Boundaries

### Animations

`eos_anim_t` represents an animation instance, and `eos_anim_group_t` coordinates the start, completion, and destruction of multiple instances. Activity transitions select animation groups through animation routing; custom cubic Bézier paths and debug interception callbacks belong to animation path capabilities and do not change the resource ownership of Activities or SNIs.

### Widget Data

`eos_wdata_set(obj, type, data, dtor)` registers typed data for LVGL objects; `eos_wdata_get` reads it; `eos_wdata_remove` deletes the specified item and calls the destructor; `eos_wdata_clear` deletes all typed data on the object. Replacing an item of the same type does not call the destructor of the old value; the caller must handle the ownership of the old value before replacement.

`EOS_WDATA_SNI_CB` specifically stores SNI control blocks, while other framework data uses their respective types, so Activity, list, message, and SNI data can coexist.

### Object Deletion Rules

LVGL parent object deletion may cascade to delete child objects. Object deletion callbacks must first notify the SNI, clear native addresses, and then allow resources that depend on the object tree to be released. Page code must not access object pointers after the deletion callback, nor use `lv_obj_set_user_data` as a framework data registry.

### Watchface and Recent Apps

The watchface component provides a unified entry point through the C API and `eos.ww`; the component is only responsible for display and data binding and does not own script programs. Recent Apps uses page snapshots and thumbnails, but cards do not own Activity Views; when evicted, they must be handed over to Activity, SPM, and SNI to complete destruction.
