# JavaScript Programs and Runtime Constraints

ElenixOS applications and watchfaces can be implemented with JavaScript scripts. Scripts run in the JavaScript engine provided by the system, accessing ElenixOS capabilities through `eos` and creating and manipulating LVGL objects through `lv`.

## Script Package Entry

A script package should contain at least the `manifest.json` required by the runtime and an entry script. The entry file name for applications and watchfaces is `main.js`. The package's API compatibility is declared by `minApiLevel` and `targetApiLevel`; when `minApiLevel` is higher than the current system API level, the application will not start.

The manifest provides the script's identity, display information, API compatibility range, and optional permission declarations. The system checks the compatibility range; unrecognized permissions will not grant capabilities.

## Runtime Constraints

- **Directly calling `script_engine` to start an application or watchface is prohibited.** Application/watchface startup, resume, suspend, and stop must be managed through SPM; the script engine is merely the execution layer used by SPM.
- Scripts execute in the system event loop; long synchronous work or blocking waits will occupy the event loop and delay other work.
- The current script context only provides the two system API namespaces `eos` and `lv`.
- LVGL/ElenixOS objects visible to JS are handles managed by the runtime. After the owning Activity, View, or native object is destroyed, the original handle can no longer be used.
- Script exceptions, parse failures, module link failures, unresponsiveness, and engine crashes are categorized and handled by the runtime; legacy internal error constants do not constitute an application interface.
- Script callbacks should return as soon as possible. When deferred processing is needed, the timing or event mechanisms provided by the runtime should be used.

## Lifecycle

A script application creates a runtime context and executes the entry on startup; when switching to another page, the application can be suspended, and when returning to the application, the same context is resumed. Recent Apps retains a limited number of suspended applications; when the memory watermark or count limit is reached, the least recently used application is fully stopped and its context released.

A script watchface runs as the root Activity. When an application is opened, the watchface pauses, and when returning to the watchface, it resumes; when switching watchfaces, uninstalling a watchface, or resetting the engine, the old watchface is destroyed.
