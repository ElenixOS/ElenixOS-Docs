# ElenixOS JavaScript API Reference

Scripts use the system APIs provided by ElenixOS through the global object `eos`. The names below come from the interfaces actually mounted by the current runtime; C APIs that are not listed do not automatically appear in JS just because a corresponding native function exists.

## `eos.view`

```js
const view = eos.view.active();
```

`active()` returns a handle to the currently active View.

## `eos.console`

```js
eos.console.log("message");
eos.console.info("info");
eos.console.warn("warning");
eos.console.error("error");
eos.console.debug("debug");
```

Each method requires at least one string argument; the current implementation only processes the first argument. Logs are prefixed with the current script ID.

## `eos.config`

```js
eos.config.setStr("key", "value");
eos.config.setBool("enabled", true);
eos.config.setNumber("count", 3);

const s = eos.config.getStr("key");
const b = eos.config.getBool("enabled");
const n = eos.config.getNumber("count");
```

Configuration is isolated by script ID: apps and watchfaces each write to `config.json` in their own data directory. Write methods have no useful return value; on read, a missing or type-mismatched string is `undefined`, a boolean is `false`, and a number is `0`. An exception is thrown when the configuration file cannot be loaded.

## `eos.time`

```js
const now = eos.time.getNow();
```

Returns an object containing the numeric fields `year`, `month`, `day`, `hour`, `min`, `sec`, `ms`, and `day_of_week`. The field value conventions match the system `eos_datetime_t`.

## `eos.appHeader`

```js
eos.appHeader.setTitle(view, "标题");
eos.appHeader.show();
eos.appHeader.hide();
```

The first argument of `setTitle` can be a View handle or `null`, and the title must be a string; passing `null`/`undefined` clears the title. `show` and `hide` operate on the app header of the current page.

## `eos.activity`

```js
const activity = eos.activity.create();
eos.activity.setType(activity, eos.ACTIVITY_TYPE_APP);
eos.activity.setTitle(activity, "详情");
eos.activity.enter(activity);

const current = eos.activity.current();
const visible = eos.activity.visible();
const view = eos.activity.getView(current);
const ok = eos.activity.back();
```

Currently available methods:

| Method | Behavior |
|---|---|
| `create()` | Creates a normal Activity and returns a handle |
| `destroy(activity)` | Destroys an Activity that is not on the stack and not visible |
| `current()` / `visible()` / `bottom()` / `watchface()` | Gets the corresponding Activity handle |
| `getView(activity)` / `setView(activity, view)` | Reads or sets the View |
| `getTitle(activity)` / `setTitle(activity, title)` | Reads or sets the title |
| `getType(activity)` / `setType(activity, type)` | Reads or sets the type |
| `setAppHeaderVisible(activity, visible)` / `isAppHeaderVisible(activity)` | Manages the app header |
| `enter(activity)` | Pushes the Activity onto the page stack and enters it |
| `back()` | Returns to the previous page, returning a boolean indicating the call result |
| `isTransitionInProgress()` | Queries whether a page transition is in progress |

`setView` only takes effect at the timing allowed by the Activity entry flow; system-managed Views are controlled by the Activity lifecycle. Although `rootScreen()` appears in the `eos.activity` name table, calling it in JS throws an "unavailable" exception, so it does not constitute an API for scripts to obtain the root screen.

The Activity type constants visible to scripts are `ACTIVITY_TYPE_NULL`, `ACTIVITY_TYPE_APP`, `ACTIVITY_TYPE_APP_LIST`, `ACTIVITY_TYPE_WATCHFACE`, and `ACTIVITY_TYPE_WATCHFACE_LIST`. C-layer types such as `INPUT_PAGE`, `LOCK_SCREEN`, and `RECENT_APPS` are currently not exported as JS root constants.

## `eos.permission`

```js
eos.permission.request("sensor", result => {
  // granted_once、granted_foreground、granted_always 或 denied
});

const state = eos.permission.check("sensor");
```

The request must use a permission name already declared in the manifest. Requests are asynchronous and will display an authorization panel when needed; when long-term or foreground authorization is already held, the callback is also asynchronous. `check` returns `once`, `foreground`, `always`, or `denied`, and returns `unknown` for unknown permissions. When a request for the same permission category is already being processed or queued, duplicate requests are dropped.

## `eos.sensor`

```js
const data = eos.sensor.readLatest(eos.SENSOR_ACCE);
const changed = eos.sensor.setSamplePeriod(eos.SENSOR_ACCE, 100);
const period = eos.sensor.getSamplePeriod(eos.SENSOR_ACCE);
```

For an initialized and valid type, `readLatest` returns a cached object; when the driver has not yet reported data, `timestamp` and the data fields are still zero, so the returned object itself does not indicate that a sample exists. It returns `null` only for an invalid type or when the underlying call fails. The returned object always has `timestamp`; accelerometer, gyroscope, and magnetometer use `x/y/z`, while other types use the corresponding fields: `heart_rate`, `spo2`, `lux`, `temp`, `pressure`, `steps`, `distance_mm`, `ecg`, or `cap`. The JS API has no raw Sensor subscription interface; for semantic subscriptions, see `eos.metric` below.

## `eos.metric`

```js
const sample = eos.metric.get("battery.percent");
const handle = eos.metric.subscribe("health.heart_rate", sample => {
  // sample contains metric, value, unit, timestamp, valid, stale
});
eos.metric.unsubscribe(handle);
```

Metric is a semantic data interface for scripts and is not equivalent to the raw sensor API. Reads return a standard sample; subscriptions invoke the callback at intervals, and the handle belongs to the current script context and becomes invalid upon unsubscribe or context cleanup. Samples may be invalid or stale; callers should use `valid`, `stale`, and `value` together to determine the sample state.

## `eos.clockHand`

```js
const hand = eos.clockHand.create(parent, "hour.png", eos.CLOCK_HAND_HOUR, 0, 0);
eos.clockHand.placePivot(hand, 10, 20);
eos.clockHand.centerStyle(hand, 10, 20);
eos.clockHand.attach(hand, eos.CLOCK_HAND_HOUR);
eos.clockHand.center(hand);
```

The image path for `create` is relative to the `assets/` directory of the current app or watchface, and the file must exist. The type uses `CLOCK_HAND_HOUR`, `CLOCK_HAND_MINUTE`, or `CLOCK_HAND_SECOND`. An exception is thrown when the arguments of any method do not match or the resource does not exist.

## `eos.ww`

`eos.ww` provides native LVGL component factories dedicated to watchfaces. The main components currently exposed include analog dials, compass dials, radial gauges, Metric rings, trend charts, and calendar grids; some components can be bound to `eos.metric` semantic names, and values or data can also be set directly by scripts. Component handles belong to the parent View passed in. The specific methods and options are subject to what SNI currently exports; this namespace is not a runtime dynamic plugin registry.

## Constants

The root object currently exports:

- Fonts: `FONT_SIZE_LARGE`, `FONT_SIZE_MEDIUM`, `FONT_SIZE_SMALL`
- Display: `DISPLAY_WIDTH`, `DISPLAY_HEIGHT` (depends on the platform display configuration)
- Clock hand: `CLOCK_HAND_HOUR`, `CLOCK_HAND_MINUTE`, `CLOCK_HAND_SECOND`
- Activity: the five `ACTIVITY_TYPE_*` listed above
- Sensors: `SENSOR_ACCE`, `SENSOR_GYRO`, `SENSOR_MAG`, `SENSOR_HR`, `SENSOR_SPO2`, `SENSOR_LIGHT`, `SENSOR_TEMP`, `SENSOR_BARO`, `SENSOR_STEP`, `SENSOR_PROXIMITY`, `SENSOR_ECG`, `SENSOR_CAP`

For the LVGL object API, see [LV API](./lvgl). For lifecycle constraints on handles and callbacks, see [SNI Architecture and Lifecycle](./sni).
