# Event Bus

The event bus synchronously broadcasts system state changes by event identifier. It is used to notify about application installation, system power and display status, script lifecycle, page switching, and language changes; it is not an asynchronous message queue, nor does it replace the Activity stack or LVGL widget events.

## Publish and Subscribe

Modules can subscribe to the events they need and unsubscribe when notifications are no longer required. Subscriptions can be associated with an object to manage the subscription lifecycle, but the associated object does not turn a global broadcast into a targeted message.

Event callbacks execute synchronously during the publish process and inherit the thread/task/interrupt context of the publisher; the Event Bus does not automatically deliver them to the LVGL main loop. Therefore, when a publisher publishes from an ISR, all subscribers may also execute within the ISR. When GUI/file/script operations are needed, callbacks should copy the necessary data and hand it off to the Dispatcher for deferred processing, or the publisher itself should defer before publishing.

The `param` provided by the publisher and the associated object are both borrowed resources: callbacks may only use them within the lifetime guaranteed by the owner; if they need to be retained across callbacks, the subscriber must copy the data or establish an explicit ownership relationship. Events such as battery changes and page switches convey service/page state, not ownership of the state object.

A callback may request to unsubscribe; if a broadcast is in progress, the actual node cleanup is deferred to a safe point. Modules should clean up associated subscriptions when the owner is destroyed to prevent callbacks from continuing to access expired objects.

Event identifiers registered at runtime are only valid within the current process instance and should not be saved as persistent protocol numbers.

The Event Bus only defines a synchronous broadcast protocol; it does not provide deferred execution, thread-safe callbacks, or background queue semantics. For cross-context submission, see [Task Scheduler](../scheduler/dispatcher).
