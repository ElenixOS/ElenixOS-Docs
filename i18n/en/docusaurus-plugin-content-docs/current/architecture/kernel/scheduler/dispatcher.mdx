# Task Dispatcher

The task dispatcher submits short tasks from other threads or interrupt contexts to the system main loop, processing them in sequence in a context suitable for executing UI and system logic. It is a deferred execution queue across contexts, not a general-purpose thread scheduler.

## Queue and Execution

The dispatcher uses a circular queue protected by a critical section to store callbacks and their user data. When queue space is insufficient, it attempts to expand; memory allocation failure may cause new tasks to be lost. Tasks in the queue are processed by the main loop in submission order, and the queue protection is released during callback execution so that other contexts can continue submitting work.

## Usage Boundaries

Submitters should keep callbacks short and ensure that user data remains valid until the task executes. In interrupts, only collect the necessary information and submit follow-up work; tasks that need to operate on LVGL must execute in the GUI main loop. The queue does not provide task priorities, cancellation, or reliable persistence guarantees.
